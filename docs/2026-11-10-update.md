# 2026-11-10 更新：问卷、转头延迟与眼动/呼吸记录

本轮同步包含上次提交后尚未上传的本地修改。

## 问卷

共享的 Likert7 问卷更新为 17 道单选题，各题 7 个选项、统一 1–7 分，按用户确认相应修改 Q1、Q2、C1 的端点说明。顺序为 Q1、Q2、D1–D3、M1–M3、P1–P3、E1、L1、C1 和三道选中反馈题。问卷资源 GUID 与三个场景的引用保持不变；E 组沉降反馈等交互保留。

## 转头与记录开销

Quest Android 构建钩子启用 Meta Quest OpenXR 的原生 Late Latching 开关；Android Vulkan 正念播放阶段在渲染前标记头部。头部姿态仍由 TrackedPoseDriver 更新，不增加平滑或路线位移。

眼动每帧快照的 CSV 数值格式化改为后台执行并复用缓冲区；原有 41 列、采样触发方式、有效性与队列统计保留。此项减少主线程格式化工作，未据此宣称真机零掉帧。

## 眼动与呼吸

采用 Quest Pro 原生合并视线，加电脑采集真实呼吸带、局域网转发的方案。每次记录的眼动 CSV、呼吸 CSV、校时 CSV 与会话 JSON 共用文件名前缀和会话标识。保留电脑样本时间、头显接收时间、校正时间、可选原始设备时间、往返时间及异常状态。

接收、格式化和写文件运行于后台线程。电脑中转程序还保存原始样本备份。没有呼吸信号时不写入样本、不补零。离线工具按可用时钟映射配对，超过允许时间距离或眼动无效时留空。

**目前没有真实呼吸带，尚未实现具体厂商的设备采集适配。** 当前只是软件记录与校时链路；设备连接、原始呼吸波形、采样率、单位及设备时钟映射仍需根据型号完成。软件不生成模拟呼吸，也不以心率或动画代替真实呼吸，不自动触发 D/E/F 的吸气事件。

使用方法与协议见 [Tools/PhysiologySync/README.md](../Tools/PhysiologySync/README.md)。脚本按默认 D 盘路径运行；在另一台电脑上，应将启动命令中的工程路径改为实际克隆目录。

## 验证与限制

- 运行时代码桌面、非 Editor Android 条件分支和编辑器脚本源码编译均通过。
- 四组软件测试通过，覆盖适配输入、无头显时电脑备份、软件校时及过期、断连恢复、暂停、乱序/序号空缺、端口占用、保存和离线配对。
- 本机端到端测试接收 105 条人工测试样本，其中 103 条具备可用软件时钟映射，队列丢行计数为 0。这只是特定测试结果，不是实际呼吸采集或性能保证。测试样本未上传。
- 眼动时间为 Unity 帧读取时刻，不是已经验证的原始传感器采样时刻。默认呼吸时间为电脑接收时刻；只有设备适配器确实完成采样时钟转换后才可标记 pc_acquisition。
- 校时 RTT 不等于传感器总延迟，也不是已证明的同步误差上界。没有 Quest Pro 和真实呼吸带测量，不宣称物理同步、毫秒级精度或零掉帧。
- 本机缺少 Android Build Support，本轮未生成 APK，也未执行 Shader、Gradle 或 IL2CPP 完整构建；需要在打包电脑重新构建并安装后验证。

Library、缓存、APK、问卷回答、生理原始记录和本机测试数据均未纳入本次提交。引用 [LSL4Unity](https://github.com/labstreaminglayer/LSL4Unity) 与 [LSL 的时间同步说明](https://labstreaminglayer.readthedocs.io/info/time_synchronization.html) 的已有思路，本工程实现使用自有 UDP 协议，不是可直接接入 LabRecorder 的 LSL 流。
